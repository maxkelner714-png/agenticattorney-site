# AgenticAttorney.com

The production repository for [agenticattorney.com](https://agenticattorney.com), a static site deployed on Netlify.

## What the site is

AgenticAttorney.com is a two-sided platform:

- A free attorney-matching service for businesses that run on AI agents. Matching currently covers New York, California, Texas and Nevada. A match request is a plain email to info@agenticattorney.com that the visitor sends from their own mail client.
- A software product for attorneys who want to serve agentic businesses.

AgenticAttorney.com is not a law firm and does not give legal advice. The site must never suggest it is one.

## Source of truth

The whole site is generated from one file: `src/prototype.html`. It is a body-only HTML fragment (markup plus one inline `<style>` and one inline `<script>`). The fragment is kept in sync with the Claude Doc "Agentic Attorney Chat Copy" and the published artifact of the prototype; whichever of those changes, the fragment is updated to match and the site is rebuilt from it.

`public/` is generated by `scripts/build.mjs` and committed, so Netlify serves it without a build step. CI rebuilds it and fails if the committed output is out of date.

## How to update the site

1. Replace `src/prototype.html` with the new fragment.
2. `node scripts/build.mjs` (or `npm run build`).
3. `npm test`.
4. Commit `src/`, `public/` and anything else that changed.

The build script takes an optional path if the fragment lives elsewhere: `node scripts/build.mjs /path/to/fragment.html`.

### What the build does

- Removes the Google Fonts `<link>` tags and self-hosts Newsreader and Geist instead (latin woff2 files from the `@fontsource-variable` packages, copied to `public/assets/fonts/` with their OFL licenses in `LICENSE.txt`).
- Moves the inline `<style>` into `public/assets/site.css` and the inline `<script>` into `public/assets/app.js`, so the site runs under a strict Content Security Policy with no inline scripts. A small `theme-init.js` runs in `<head>` to apply a stored theme before first paint.
- Writes `public/index.html` as a full document with meta tags, Open Graph and Twitter cards, canonical URL, theme colors, favicon links, font preloads and a `<noscript>` block.
- Writes the legal pages, `404.html`, `_headers` (CSP and security headers), `_redirects`, `robots.txt` and `sitemap.xml`.
- Refuses to build if the fragment contains inline event handlers, since the CSP would block them.

The CSP allows `style-src 'unsafe-inline'` because the prototype's script sets a `style` attribute on the self-audit progress meter. Scripts are always `'self'` only.

## Local run

```
npm ci
npm run build
npm start          # serves public/ on http://localhost:4190 (PORT overrides)
npm test           # Playwright, Chromium only
```

`scripts/serve.mjs` has no dependencies and applies `_headers` and `_redirects` the way Netlify does, so what passes locally is what ships.

## Deploy to Netlify

1. Import the repository in Netlify.
2. Publish directory: `public`. Build command: leave empty. `netlify.toml` already says this.
3. Check the deploy preview. Headers and rewrites come from `public/_headers` and `public/_redirects`.
4. The domain switch to agenticattorney.com comes last, after the owner approves the preview.

## Where the legal pages and assets come from

- Legal pages: `scripts/build.mjs` looks for `terms.html`, `privacy.html` and `disclaimers.html` in `/mnt/project-files/website/legal/`. A fragment is wrapped in the site shell with the site CSS and a link home; a full document is copied as is. When a file is absent, the build writes an interim page that says the page is being prepared and gives info@agenticattorney.com. They are served at `/terms`, `/privacy` and `/disclaimers`.
- Assets: files in `/mnt/project-files/website/assets/` (favicon.svg, favicon.png, apple-touch-icon.png, og-image.png) are copied into `public/`. When no favicon is provided the build generates a simple one (a section mark in terracotta on an off-white rounded square).

Both folders are inputs to the build, not part of the repository. Run the build on a machine that has them to pick up new versions.
